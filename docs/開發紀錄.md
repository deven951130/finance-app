# 開發紀錄與待辦

給接手的人看：每個階段做了什麼、當時自己決定了哪些規則，以及還沒做的改進。
專案規則和慣例請先看根目錄的 `CLAUDE.md`。

## 各階段重點

### 第一階段：設定、預算、記帳、固定支出
- 建立三層結構：`app.py`（畫面）、`db.py`（SQL）、`models/`（純計算）。
- `settings` 用 key/value 表；要加新設定只要在 `db.DEFAULT_SETTINGS` 加一行，`INSERT OR IGNORE` 不會覆蓋使用者改過的值。
- 預算類別只定義在 `models/budget.py` 的 `CATEGORIES`。
- **「本月還能花多少」= 四個類別預算總和 − 本月支出總和**（不含收入和固定支出，是使用者當時要求的定義）。

### 第二階段：負債、每月現金流、持股
- 「已還一期」在同一個交易裡扣負債剩餘和手上現金。自己決定的規則：
  - 最後一期剩的比每月還款少時，只扣剩下的。
  - 手上現金不夠時顯示錯誤、兩邊都不扣。
  - 預計還清月份假設下一期在下個月繳。
- 持股同代號在不同帳戶各存一列，顯示時合併（加權平均均價）。「更新現價」會改掉該代號所有列。
- 損益是帳面損益，未扣賣出費用。回本價 = 總成本 ÷ (股數 × (1 − 0.001425 − 0.003))，只對虧損個股顯示。
- 單檔占總市值 **超過** 40% 才警告（剛好 40% 不警告）。

### 第三階段：交易工具、匯出、範例資料
- 下單前檢查：五項全勾且金額 ≤ 手上現金才可以下單；不通過時**列出全部原因**。旁邊的「參考」資訊不影響判斷。
- 交易紀錄：買進／賣出／當沖；總覽頁顯示本月當沖次數（> 0 紅色警告）。
- 定期定額：每月月底投入；月報酬率用 `(1 + 年報酬率)^(1/12) − 1`；4% 法則 = 總額 × 4% ÷ 12。
- CSV 匯出：每張表一個 CSV 打包成 zip，全程在記憶體處理，`utf-8-sig` 讓 Excel 不亂碼。
- 修過的 bug：`$金額$` 被 Streamlit 當成 LaTeX（改成「元」）；回本價欄位顯示 None（改空白）。

### 打包成 exe
- PyInstaller，入口是 `run_app.py`（代替 `streamlit run app.py`），只接受 localhost 連線。
- exe 版資料放在 `~/FinanceApp/finance.db`，錯誤寫到 `~/FinanceApp/error.log`，閃退時視窗會停住顯示錯誤。
- `requirements-build.txt` 保持純 ASCII（Windows pip 用 cp950 讀檔）。
- exe 版主題（2026-10-13）：`FinanceApp.spec` 把 `.streamlit/config.toml` 打包到 `app.py` 旁邊的 `.streamlit/`。Streamlit 1.65 除了讀「工作資料夾」的設定，也會讀「主程式旁邊」的 `.streamlit/config.toml`，所以**不需要**在 `run_app.py` 用 `os.chdir` 切換工作資料夾（少一個會影響相對路徑的副作用）。驗證：從 exe 所在資料夾啟動有主題；把打包進去的設定檔拿掉就變回 Streamlit 預設樣式。

### 上架前的隱私檢查（2026-10-13）
- 發現用原始碼執行（`streamlit run app.py`）時，Streamlit 預設監聽 `0.0.0.0`，同一個網路的其他電腦可以直接打開 app、看到和匯出資料；也預設會傳送使用統計。exe 版因為 `run_app.py` 有設定所以沒問題。修正：`.streamlit/config.toml` 加上 `server.address = "localhost"`、`browser.gatherUsageStats = false`（和 `run_app.py` 一樣）。
- `FinanceApp.spec` 原本打包整個 `models/` 資料夾，會把 `__pycache__/*.pyc` 一起帶進 exe，.pyc 裡有打包電腦上的絕對路徑。改成只打包 `models/*.py`。
- `.gitignore` 加上 `*.bak`、`*.log`、`.claude/`（手動備份、錯誤紀錄、Claude Code 本機設定）。

### 介面美化
- `.streamlit/config.toml`：墨藍主色、米白背景、深色側邊欄、思源黑體。
- 每頁結構：頁首說明 → 數字卡 → 白色卡片。側邊欄分「日常 / 投資 / 其他」，用 `st.navigation(position="hidden")` 自己畫。
- 手機（640px 以下）明細列維持同一列；使用者文字用 `html.escape`。
- 測試總數 44 個（2026-10 時）。

### 存摺風格改版與全面測試（2026-10-13）
- 設計概念是台灣人熟悉的「存摺」：淡青灰的紙（`#EDF1EE`）、墨色的字，金額和標題用思源宋體，明細一列一列用橫線隔開，合計列上面畫會計帳的雙線。
- 總覽最上面是唯一的主角「淨資產」大數字，旁邊列出它怎麼算出來的；原本四張一樣大的數字卡拿掉了。
- 其他頁的一排數字改成「摘要列」（`summary_strip()`）：上面一條墨色粗線，格子之間用直線隔開。
- 自律提醒（集中、當沖、超支）改成存摺的「摘要」欄（`notices()`），不再用 Streamlit 的紅黃色塊；紅綠只留給漲跌。
- 下單前檢查的結論「先不要下單／可以下單」放在頁面最上面的大字，用 `st.empty()` 先佔位置、算完再填。
- 類別顏色刻意不用墨藍和金色，因為這兩個顏色在預算條上代表「正常」和「快用完」。
- 用 4 個測試 agent（AppTest 實際操作 10 頁、程式審查、發布與隱私稽核）加 1 個驗證 agent 全面測過，修掉的問題：
  - 設定頁、預算頁連按兩次「儲存」，第二次的值會被丟掉（改版前就有）→ 存檔後用 `done()` 立刻重跑。
  - 表單送出後側邊欄摘要慢一拍（改版前就有）→ 同上。
  - 備註、名稱裡有兩個 `$` 會變成數學公式（改版前就有）→ `plain()`。
  - 淨資產大數字在 1024px 寬時從中間斷行 → 不斷行、字級跟著視窗縮。
  - 橘色、紅綠小字、「已還清」金色標籤的對比不足 → 改用算過對比的顏色。
  - 預算 0 卻有花錢時進度條是金色 → 改成橘色（超支）。
  - 定期定額報酬率是負的時候，資產線被本金面積蓋住 → 資產線畫在最上層。
  - `config.toml` 的字型備援清單被 Streamlit 當成網址的一部分 → 網址只寫一個字型，備援寫在 CSS。

### v1 實用功能與安裝版改版（2026-10-21）
- 目標：讓第一次用的人知道從哪裡開始、每天記帳更快、資料不會不見。
- 總覽：沒有任何資料時（`db.is_empty()`）改成顯示三步驟引導；有資料時多「淨資產變化」折線圖（`networth_history`，每天打開總覽時覆蓋當天那筆，至少兩天才畫）。
- 記帳：月份選單（本月一定在選單裡）、每列的「修改」小視窗（`update_expense`）、最近 6 個月依類別疊起來的長條圖與預算虛線（`models/budget.py` 的 `last_n_months`、`monthly_totals`）。
- 側邊欄「記一筆」：日期固定今天，要補記以前的到記帳頁。
- 還款紀錄：`debt_payments` 表，`pay_debt_installment` 在同一個交易裡多記一筆。自己決定的規則：這個月已經還過，就不顯示「已還一期」按鈕，改成「本月已還」+ 需要再確認的「提前再還一期」（不完全禁止，因為有人會一次繳兩期）。
- 自動備份：每天第一次打開（每個瀏覽器分頁只檢查一次）用 SQLite 的 `backup()` 複製到資料庫旁的 `backups/`，留 14 份；還原前另存一份 `...-before-restore.db`，這種檔案不會被自動刪。備份失敗不影響開啟，只在設定頁顯示。
- 圓餅圖：Altair 內建圖例在窄卡片會蓋到圓圈，改成自己用 HTML 畫圖例並顯示百分比（待辦 21）。設定頁路徑把家目錄顯示成 `~`（待辦 22）。
- 測試 44 → 83：`tests/test_db_features.py`、`tests/test_app.py`（AppTest 跑每一頁和主要操作）。
- **安裝版改用官方嵌入式 Python**：在使用者電腦（Trend Micro Apex One）實測，安裝 0.0.8 後 PyInstaller 的 FinanceApp.exe 立刻被刪除，捷徑點了沒反應。改成 `installer/build_runtime.py` 準備「python.org 嵌入式 Python + 套件 + 原始碼」，捷徑執行有官方簽章的 `pythonw.exe run_app.py`；用 AppUserModelID 和 `WM_SETICON` 讓工作列、視窗顯示理財系統圖示。實測同一台電腦可以正常開啟、畫面正常。
- 同一台電腦上，PyInstaller 和 Inno Setup 自己編譯也會被防毒擋（`EndUpdateResource failed`），安裝檔改由 GitHub Actions 產生。
